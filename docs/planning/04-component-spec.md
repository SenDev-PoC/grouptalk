# 모둠톡 논리적 컴포넌트 명세

## 이 문서의 역할

이 문서는 [03-system-architecture.md](03-system-architecture.md)의 여섯 논리적 책임이 무엇을 맡고 무엇을 맡지 않는지, 어떤 의미의 정보를 주고받으며 실패할 때 사용자에게 무엇을 보장해야 하는지 설명한다.

여기서 컴포넌트는 제품 책임을 이해하기 위한 개념이다. 실제 프로그램·서비스·배포 단위가 아니다.

## 공통 책임 원칙

- 각 컴포넌트는 하나의 사용자 또는 정보 결과를 책임진다.
- 입력과 결과는 의미 수준으로만 설명한다.
- 실패를 숨기거나 정상 상태로 바꾸어 표시하지 않는다.
- 자동 해석은 교사의 최종 판단을 대신하지 않는다.
- 학생 이름과 익명 화자 표시를 자동으로 연결하지 않는다.
- 구체적인 구현 형식은 17:30 이후 결정한다.

## 책임 1. 활동 운영

### 한 문장 책임

교사가 활동을 준비·시작·종료하고 모든 사용자가 같은 활동 상태를 이해하게 한다.

### 의미 입력

- 교사가 선택한 활동 이름과 주제
- 활동에 참여할 모둠
- 교사의 시작·종료 결정
- 모둠 준비 상태

### 의미 결과

- 준비 전, 진행 중, 종료 상태
- 교사와 모둠 공용 기기에 일관된 활동 상태
- 시작 전 준비 상태와 종료 후 수집 종료 안내

### 협력 대상

- 모둠 준비: 어떤 모둠이 준비됐는지 받는다.
- 대화 수집 상태: 활동 시작·종료의 의미를 전달한다.
- 정보 수명과 투명성: 종료 시 남는 정보와 미결정을 설명한다.

### 책임지지 않는 것

- 대화 내용과 참여 경향 해석
- 개인 학생 출석·신원·평가
- 구체적인 화면·저장·전송 방식

### 실패 시 보장할 사용자 상태

- 시작 결정이 모든 사용자에게 아직 전달되지 않았다면 진행 중으로 단정하지 않는다.
- 종료 의도가 확인되면 실시간 수집이 계속되는 것처럼 보이지 않게 한다.
- 사용자는 현재 활동 상태와 다시 확인할 행동을 안다.

## 책임 2. 모둠 준비

### 한 문장 책임

모둠 공용 기기가 올바른 활동과 모둠을 확인했고 준비됐음을 교사와 모둠에 알린다.

### 의미 입력

- 들어온 활동과 토의 주제
- 사용자가 선택한 모둠
- 선택 확인 또는 다시 선택 행동
- 활동의 현재 상태

### 의미 결과

- 선택한 활동·모둠 확인
- 준비 전, 준비됨, 확인 필요, 늦은 입장 상태
- 교사가 보는 모둠별 준비 상태

### 협력 대상

- 활동 운영: 현재 활동과 시작 상태를 받는다.
- 대화 수집 상태: 준비된 공용 기기가 수집 상태로 이동할 수 있게 한다.

### 책임지지 않는 것

- 개인 학생의 출석 여부
- 모둠원의 실제 신원 확인
- 모둠 대화의 참여 해석

### 실패 시 보장할 사용자 상태

- 잘못 선택한 모둠을 시작 전에 다시 선택할 수 있다.
- 중복 공용 기기가 학생 참여 인원으로 오해되지 않는다.
- 늦은 입장은 참여 부족이 아니라 준비 상태로 표시된다.

## 책임 3. 대화 수집 상태

### 한 문장 책임

모둠 공용 기기의 대화 전달이 대기·수집·정보 부족·연결 실패·종료 중 어디에 있는지 사용자에게 알린다.

### 의미 입력

- 활동 시작·종료 상태
- 모둠 공용 기기의 연결과 수집 상태
- 대화 정보의 유무와 최신성
- 다시 연결 또는 연결 종료 행동

### 의미 결과

- 모둠 공용 기기의 대기·수집·실패·종료 안내
- 교사가 보는 정보 있음·정보 부족·갱신 중단 상태
- 참여 상태 해석이 결론을 내릴 수 있는지에 대한 신뢰 정보

### 협력 대상

- 활동 운영: 시작·종료 상태를 받는다.
- 참여 상태 해석: 정보 유무와 최신성을 제공한다.
- 교사 상황 인식: 연결 문제와 최근 상태를 제공한다.
- 정보 수명과 투명성: 수집 목적과 정보 수명 안내를 받는다.

### 책임지지 않는 것

- 참여 경향의 의미 해석
- 학생 신원 판단
- 원본 음성 장기 보존을 전제로 한 기능

### 실패 시 보장할 사용자 상태

- 연결 실패를 참여 편중처럼 표시하지 않는다.
- 모둠 공용 기기는 연결 확인과 다시 연결 행동을 안다.
- 교사는 마지막 상태가 현재 상태처럼 보이지 않게 최신성을 확인한다.

## 책임 4. 참여 상태 해석

### 한 문장 책임

익명 화자의 대화 정보에서 교사가 더 살펴볼 참여 경향과 판단할 수 없는 상태를 구분한다.

### 의미 입력

- 모둠과 활동 맥락
- 익명 화자별 대화 정보
- 정보의 양과 최신성
- 활동이 진행 중인지 종료됐는지에 대한 상태

### 의미 결과

- 여러 익명 화자가 고르게 참여하는 경향
- 한 익명 화자 중심 경향
- 정보 부족
- 판단 불가와 이유
- 결과의 최신성과 한계

### 협력 대상

- 대화 수집 상태: 정보 유무·최신성·연결 상태를 받는다.
- 교사 상황 인식: 참여 경향과 판단 한계를 전달한다.
- 정보 수명과 투명성: 파생 정보의 목적과 수명 원칙을 따른다.

### 책임지지 않는 것

- 학생 개인 식별
- 학생 능력·성취·태도 평가
- 교사의 최종 수업 판단과 자동 개입
- 구체적인 해석 방법·기준값·성능 보증

### 실패 시 보장할 사용자 상태

- 근거가 부족하면 정보 부족 또는 판단 불가로 남긴다.
- 오래된 정보가 새로운 참여 경향처럼 보이지 않는다.
- 자동 해석의 결과와 학생 평가를 분명히 구분한다.

## 책임 5. 교사 상황 인식

### 한 문장 책임

교사가 여러 모둠의 참여 경향·정보 최신성·연결 상태를 비교하고 먼저 살펴볼 후보를 찾게 한다.

### 의미 입력

- 활동과 모둠 상태
- 참여 경향과 판단 한계
- 정보 최신성과 연결 상태
- 교사가 선택한 모둠과 활동 종료 행동

### 의미 결과

- 모둠별 상태 요약
- 먼저 살펴볼 후보와 이유
- 정보 부족·판단 불가·연결 실패의 구별
- 교사가 취할 다음 행동

### 협력 대상

- 활동 운영: 활동·모둠·진행 상태를 받는다.
- 참여 상태 해석: 참여 경향과 한계를 받는다.
- 대화 수집 상태: 정보 최신성과 연결 상태를 받는다.

### 책임지지 않는 것

- 교사를 대신한 자동 수업 개입
- 참여 경향을 학생 평가로 바꾸는 일
- 모든 대화 내용을 한 화면에 동일한 중요도로 보여 주는 일

### 실패 시 보장할 사용자 상태

- 분석 결과가 없더라도 모든 모둠과 그 데이터 상태를 확인할 수 있다.
- 연결 실패와 참여 편중이 서로 다른 다음 행동으로 이어진다.
- 교사는 불확실한 상태의 이유를 볼 수 있다.

## 책임 6. 정보 수명과 투명성

### 한 문장 책임

대화와 파생 정보의 목적·열람 주체·보존·삭제·한계를 사용자와 실제 도입 검토자에게 드러낸다.

### 의미 입력

- 원본 음성·전사문·익명 화자 표시·참여 지표·요약의 구분
- 활동 시작·수집·종료 상태
- 실제 시연과 학교 도입의 맥락
- 확정된 정보 원칙과 아직 정하지 않은 항목

### 의미 결과

- 수집 목적과 교사가 본다는 안내
- 정보 종류별 기본 원칙과 미결정
- 활동 종료와 정보 보존 종료의 구분
- 실제 학생 검증 전 확인해야 할 질문

### 협력 대상

- 모든 논리적 책임: 사용자에게 정보 의미와 한계를 설명한다.
- 학교·개인정보 책임자: 실제 도입 전 결정할 항목을 제공한다.

### 책임지지 않는 것

- 법률·정책 적합성의 자동 판정
- 이름이 없는 정보를 자동으로 익명정보라고 보증하는 일
- 제품 목적과 관계없는 정보 수집

### 실패 시 보장할 사용자 상태

- 정보 수명이 정해지지 않았으면 미결정으로 명시한다.
- 실제 학생 데이터와 합성 시연 데이터를 구분한다.
- 사용자는 수집 목적·보는 사람·종료 상태를 이해할 수 있다.

## 책임 협력표

| 보내는 책임 | 받는 책임 | 전달하는 의미 | 사용자 결과 |
|---|---|---|---|
| 모둠 준비 | 활동 운영 | 어느 모둠 공용 기기가 준비됐는가 | 교사가 시작 전에 준비 상태를 안다. |
| 활동 운영 | 대화 수집 상태 | 활동이 시작·종료됐는가 | 모둠 기기의 수집 상태가 활동과 일치한다. |
| 대화 수집 상태 | 참여 상태 해석 | 정보가 있고 최근이며 연결됐는가 | 근거가 부족할 때 결론을 유보한다. |
| 참여 상태 해석 | 교사 상황 인식 | 어떤 참여 경향과 한계가 있는가 | 교사가 먼저 살펴볼 후보를 찾는다. |
| 대화 수집 상태 | 교사 상황 인식 | 연결·최신성 상태는 무엇인가 | 교사가 참여 문제와 기술 문제를 구분한다. |
| 정보 수명과 투명성 | 모든 책임 | 정보 목적·열람·수명·한계는 무엇인가 | 학생과 교사가 정보 사용을 오해하지 않는다. |

## 핵심 시연과 책임 연결

| 핵심 단계 | 주 책임 | 반드시 보이는 실패·경계 |
|---|---|---|
| 활동 준비 | 활동 운영 | 준비 전 모둠이 있어도 상태를 숨기지 않음 |
| 모둠 확인 | 모둠 준비 | 잘못 선택한 모둠을 다시 선택함 |
| 활동 시작 | 활동 운영 | 교사와 모둠의 상태 불일치를 피함 |
| 대화 수집 | 대화 수집 상태 | 정보 부족·연결 실패·최신성 |
| 먼저 살펴볼 모둠 찾기 | 교사 상황 인식 | 편중 경향·판단 불가·연결 문제의 구별 |
| 활동 종료 | 활동 운영 | 수집 종료와 정보 수명 미결정의 구별 |

## 미결정

- 실제 구현에서 책임을 나누거나 묶는 방식
- 참여 상태 해석의 구체 기준과 검증 방법
- 정보 종류별 실제 보존 기간과 삭제 책임자
- 대상 학교급에 맞는 정보 안내 문구

미결정은 실제 구현 단위나 기술을 이 명세가 미리 고정하지 않기 위한 의도적인 경계다.
