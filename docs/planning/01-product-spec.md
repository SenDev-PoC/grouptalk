# 모둠톡 제품 명세

## 이 문서의 역할

이 문서는 모둠톡이 누구의 어떤 문제를 왜 해결하며, 핵심 시연에서 무엇을 약속하고 무엇을 약속하지 않는지 정하는 제품 기준 문서다.

이 문서는 비실행형 기획 문서다. 구체적인 구현 형식은 17:30 이후 새 저장소에서 결정한다.

## 한 문장 제품 정의

모둠톡은 여러 모둠이 동시에 대화하는 수업에서 교사가 각 모둠의 참여 상태를 빠르게 파악하고, 지금 먼저 살펴볼 모둠을 찾도록 돕는 수업 지원 도구다.

## 해결하려는 문제

교실의 모둠 활동에서는 여러 대화가 동시에 진행된다. 교사는 모든 모둠의 대화를 계속 직접 들을 수 없으므로, 어느 모둠이 원활하게 참여하고 있고 어디에 추가 확인이 필요한지 놓치기 쉽다.

모둠톡이 다루는 핵심 문제는 대화 전체를 대신 판단하는 것이 아니다. 교사의 제한된 주의 안에서 **지금 어느 모둠을 먼저 살펴볼지** 판단할 실마리를 제공하는 것이다.

이 문제 정의는 현재 제품 가설이다. 실제 교사·학생 연구로 교육 효과가 검증된 결론은 아니다.

## 사용자와 이해관계자

| 역할 | 원하는 결과 | 제품과 만나는 지점 |
|---|---|---|
| 교사 | 여러 모둠 중 먼저 살펴볼 곳을 빠르게 찾는다. | 활동 준비, 모둠 준비 확인, 활동 시작, 실시간 상태 확인, 활동 종료 |
| 학생과 모둠 | 대화 수집의 목적과 현재 상태를 이해하며 활동에 참여한다. | 모둠 공용 기기의 모둠 확인, 대기, 수집 상태, 연결 실패, 종료 |
| 모둠 공용 기기 담당자 | 올바른 모둠을 선택하고 연결 문제를 해결한다. | 모둠 선택, 준비 알림, 다시 연결, 수집 종료 |
| 학교·개인정보 책임자 | 실제 학생 정보가 최소한으로 투명하게 다뤄지는지 판단한다. | 실제 도입 전 정보 목적·열람·보존·삭제 검토 |
| 해커톤 심사자 | 짧은 시연에서 문제, 핵심 가치, 한계, 구현 가능성을 구분한다. | 종이 프로토타입과 이후 동작 시연 |

핵심 대상 학교급과 만 14세 미만 포함 여부는 아직 정하지 않았다. 이번 기획은 특정 학년을 전제하지 않으며, 실제 학생 검증 전에 결정해야 한다.

## 핵심 제품 가치

1. 교사는 모든 대화를 읽지 않고도 먼저 살펴볼 모둠을 찾는다.
2. 교사는 참여 문제, 정보 부족, 연결 실패를 서로 다른 상태로 이해한다.
3. 모둠 공용 기기는 준비·수집·실패·종료 상태를 분명히 안다.
4. 참여 정보는 학생 평가가 아니라 교사의 수업 지원 신호로 제시된다.
5. 자동 해석과 정보 최신성의 한계가 숨겨지지 않는다.

## 핵심 시연 범위

핵심 시연은 다음 여섯 단계를 처음부터 끝까지 보여 준다.

1. 활동 준비
2. 모둠 확인
3. 활동 시작
4. 대화 수집
5. 먼저 살펴볼 모둠 찾기
6. 활동 종료

핵심 시연이 성공하면 교사는 여러 모둠의 상태를 비교해 한 모둠을 먼저 확인할 이유를 이해하고, 모둠 공용 기기는 대화 수집의 시작과 종료를 이해한다.

## 전체 제품 지도와 확장 범위

전체 제품 지도에는 다음 능력을 표시할 수 있지만 핵심 시연의 필수 완료 조건으로 요구하지 않는다.

- 대화 단계 표시
- 활동 주제와의 관련성 보조 판단
- 관련성 판단 근거
- 대화 요약과 주요 키워드
- 활동 종료 후 모둠별 보고
- 활동·모둠 구성의 재사용

확장 능력은 핵심 가치가 동작한 뒤 추가한다. 핵심 시연을 완성하지 못한 상태에서 확장 기능을 먼저 구현하지 않는다.

## 제품 규칙

### 활동과 모둠

- 교사는 활동을 준비하고 시작·종료한다.
- 모둠은 교사가 비교·관찰하는 기본 단위다.
- 모둠당 하나의 공용 기기가 활동과 모둠을 확인하고 대화 수집 상태를 보여 준다.
- 교사와 모둠 공용 기기는 같은 활동 상태를 이해해야 한다.

### 참여 상태

- 참여 상태는 익명 화자의 발화 경향을 바탕으로 교사가 더 살펴볼 곳을 찾도록 돕는 신호다.
- 참여 상태는 학생 개인의 능력·성취·태도를 평가하는 점수가 아니다.
- 익명 화자 표시는 학생 이름과 같다고 가정하지 않는다.
- 정보가 부족하거나 오래됐거나 연결이 끊긴 경우에는 참여 상태를 단정하지 않는다.

### 사용자에게 보이는 상태

- 준비 전과 준비됨을 구분한다.
- 수집 중과 정보 부족을 구분한다.
- 참여 편중 경향과 연결 실패를 구분한다.
- 판단할 수 없음과 데이터가 없음의 이유를 가능한 범위에서 설명한다.
- 활동 종료 후에는 더 이상 대화가 수집되지 않는다는 사실을 양쪽에 알린다.

## 정보와 개인정보 원칙

모둠톡은 다음 정보를 서로 다른 것으로 구분한다.

| 정보 | 제품 목적 | 기본 원칙 | 아직 정할 것 |
|---|---|---|---|
| 원본 음성 | 활동 중 대화를 참여 상태로 이해하기 위한 입력 | 장기 보존을 핵심 가치로 삼지 않는다. | 처리 중 남는 범위와 즉시 삭제 확인 방식 |
| 전사문 | 대화 흐름과 참여 상태를 이해하기 위한 중간 정보 | 이름을 붙이지 않아도 민감한 내용이 있을 수 있다고 본다. | 실제 시연 이후 보존 여부와 기간 |
| 익명 화자 표시 | 같은 대화 안에서 발화 경향을 구분 | 학생 이름과 자동으로 연결하지 않는다. | 오류와 재식별 위험을 사용자에게 설명하는 방식 |
| 참여 지표 | 교사가 살펴볼 모둠을 찾는 보조 신호 | 학생 평가에 사용하지 않는다. | 활동 후 보존 여부와 교사 외 열람 범위 |
| 요약·키워드 | 확장 범위에서 교사의 빠른 내용 파악을 보조 | 자동 생성 결과의 한계와 근거를 함께 알린다. | 외부 처리와 보존·삭제 원칙 |

해커톤 시연은 실제 학생 데이터 대신 합성 데이터 또는 충분히 고지하고 동의한 성인 참여자 데이터를 사용한다.

## 성공의 의미

제품은 다음 변화가 관찰될 때 핵심 가치를 보여 준다.

- 교사가 한눈에 정상 흐름, 참여 편중 경향, 정보 부족, 연결 실패를 구분한다.
- 교사가 먼저 확인할 모둠과 그 이유를 설명할 수 있다.
- 모둠 공용 기기가 올바른 모둠과 현재 수집 상태를 확인한다.
- 오류가 생겼을 때 사용자가 다음 행동을 이해한다.
- 종료 후 양쪽 모두 대화 수집이 끝났음을 안다.
- 참여 정보가 학생 평가나 확정 진단으로 오해되지 않는다.

자세한 관찰 조건은 [08-acceptance-tests.md](08-acceptance-tests.md)가 기준이다.

## 비목표

- 교사를 대신해 자동으로 모둠에 개입하지 않는다.
- 학생 개인을 자동 식별하거나 평가하지 않는다.
- 모든 교실 환경에서 음성·화자 구분의 정확성을 보증하지 않는다.
- 해커톤 기획만으로 실제 학교 도입의 법률·정책 적합성을 확정하지 않는다.
- 구체적인 기술·저장·전송·배포 방식을 이 문서에서 정하지 않는다.
- 종이 프로토타입 영상과 촬영 계획을 이번 패키지에 포함하지 않는다.

## 확정 결정과 미결정

### 확정 결정

- 전체 제품은 지도 수준으로, 핵심 시연 6단계는 검토 가능한 깊이로 설명한다.
- 교사의 핵심 판단은 지금 어느 모둠을 먼저 살펴볼지 찾는 것이다.
- 참여 정보는 수업 지원 신호이며 학생 평가 근거가 아니다.
- 보조 분석과 사후 보고는 핵심 시연의 필수 범위가 아니다.
- 해커톤 시연에는 실제 학생 데이터를 사용하지 않는다.

### 미결정

- 대상 학교급과 만 14세 미만 포함 여부
- 실제 학생 검증 전 고지·동의·권리 행사 방식
- 정보 종류별 실제 보존 기간과 삭제 책임자
- 실제 교실에서 참여 경향이 유효한 수업 유형과 오해를 부르는 수업 유형

이 미결정은 핵심 해커톤 시연을 막지 않지만 실제 학생 대상 검증 전에 반드시 정해야 한다.
