# 모둠톡 의미 수준 상호작용 계약

## 비실행형 경계

이 문서는 논리적 책임 사이 상호작용의 목적, 정보 범주, 성공과 실패의 의미를 설명하는 **비실행형 의미 계약**이다. 실제 전송 형식과 구현 식별자는 17:30 이후 새 저장소에서 결정한다.

제품 규칙은 [01-product-spec.md](01-product-spec.md), 사용자 순서는 [02-user-flow.md](02-user-flow.md), 책임 경계는 [04-component-spec.md](04-component-spec.md), 정보 개념은 [05-data-model.md](05-data-model.md)가 기준이다.

## 계약 원칙

- 모든 상호작용은 하나 이상의 사용자 결과에 근거한다.
- 정보가 없거나 오래됐거나 전달되지 않은 상태를 성공처럼 표현하지 않는다.
- 참여 경향과 연결 상태를 분리한다.
- 익명 화자 표시와 학생 이름을 동일시하지 않는다.
- 정보 목적·열람·수명·한계를 상호작용에서 잃지 않는다.
- 내부 형식보다 사용자가 이해할 성공·실패 의미를 우선한다.

## 상호작용 지도

| 상호작용 | 시작 주체 | 받는 책임 | 사용자 목적 |
|---|---|---|---|
| 활동 준비 공유 | 교사 | 활동 운영 | 활동·주제·모둠을 시작 전에 이해한다. |
| 모둠 확인 | 모둠 공용 기기 | 모둠 준비 | 올바른 활동·모둠에 들어왔음을 확인한다. |
| 준비 상태 전달 | 모둠 준비 | 활동 운영·교사 상황 인식 | 교사가 어느 모둠이 준비됐는지 본다. |
| 활동 시작·종료 공유 | 교사 | 활동 운영·대화 수집 상태 | 교사와 모둠이 같은 활동 상태를 이해한다. |
| 대화 수집 상태 전달 | 모둠 공용 기기 | 대화 수집 상태 | 수집·실패·종료 상태를 양쪽이 안다. |
| 참여 상태 제공 | 참여 상태 해석 | 교사 상황 인식 | 교사가 먼저 살펴볼 모둠을 찾는다. |
| 최신성·연결 상태 제공 | 대화 수집 상태 | 교사 상황 인식 | 참여 문제와 기술 문제를 구분한다. |
| 정보 목적·수명 안내 | 정보 수명과 투명성 | 모든 사용자 접점 | 대화 정보가 왜 쓰이고 무엇이 미결정인지 안다. |
| 확장 분석 제공 | 확장 분석 책임 범주 | 교사 상황 인식 | 핵심 시연 이후 대화 내용을 추가로 파악한다. |

## 계약 1. 활동 준비 공유

### 목적

교사가 준비한 활동을 모든 사용자가 같은 수업 맥락으로 이해한다.

### 시작 조건

교사가 활동 이름·주제·모둠을 검토했다.

### 정보 범주

- 활동 이름과 주제
- 참여할 모둠
- 준비 전 활동 상태
- 대화 정보의 사용 목적

### 성공의 의미

교사는 준비할 모둠을 보고, 모둠 공용 기기는 들어온 활동과 주제를 확인할 수 있다.

### 실패의 의미와 책임

활동 맥락을 확인할 수 없으면 모둠 준비를 완료한 것으로 보지 않는다. 사용자는 다시 확인할 수 있어야 한다.

### 개인정보 기대

해커톤 시연에서는 실제 학급·학생을 알아볼 수 있는 내용을 쓰지 않는다.

## 계약 2. 모둠 확인

### 목적

모둠 공용 기기가 올바른 활동과 모둠을 선택했음을 양쪽에 알린다.

### 시작 조건

공용 기기가 활동에 들어왔고 선택 가능한 모둠을 볼 수 있다.

### 정보 범주

- 사용자가 알아보는 활동과 모둠
- 선택 확인 또는 다시 선택 의도
- 현재 활동 상태

### 성공의 의미

모둠은 자기 선택을 확인하고, 교사는 해당 모둠의 공용 기기가 준비됐음을 본다.

### 실패의 의미와 책임

선택이 불분명하거나 잘못됐으면 준비됨으로 표시하지 않는다. 모둠은 다시 선택할 수 있다.

### 개인정보 기대

공용 기기 상태를 개인 학생 출석이나 신원으로 바꾸지 않는다.

## 계약 3. 준비 상태 전달

### 목적

교사가 시작 전에 모둠별 준비 상태를 이해한다.

### 시작 조건

모둠 공용 기기가 활동과 모둠을 확인했거나 아직 확인하지 않았다.

### 정보 범주

- 모둠 이름
- 준비 전·준비됨·확인 필요·늦은 입장
- 상태가 바뀐 의미

### 성공의 의미

교사는 준비되지 않은 모둠을 알고도 시작 여부를 판단할 수 있다.

### 실패의 의미와 책임

최근 상태를 알 수 없으면 준비됨으로 단정하지 않는다. 교사는 확인 필요를 본다.

### 개인정보 기대

준비 상태는 모둠 공용 기기 상태이며 개인별 참여 기록이 아니다.

## 계약 4. 활동 시작·종료 공유

### 목적

교사의 시작·종료 결정과 모둠 공용 기기의 수집 상태를 일치시킨다.

### 시작 조건

교사가 활동 상태를 변경하기로 결정했다.

### 정보 범주

- 준비·진행·종료의 의미
- 상태 변화의 주체와 시점에 대한 사용자용 설명
- 상태 변화 후 가능한 행동

### 성공의 의미

시작 시 양쪽은 활동이 진행 중임을 알고, 종료 시 양쪽은 대화 수집이 끝났음을 안다.

### 실패의 의미와 책임

상태가 일치하지 않으면 사용자는 진행 중으로 단정하지 않고 다시 확인할 행동을 본다. 종료 의도가 확인된 경우 계속 수집되는 것처럼 표시하지 않는다.

### 개인정보 기대

종료는 실시간 수집 종료를 뜻하지만, 모든 파생 정보의 즉시 삭제를 자동으로 뜻하지 않는다. 남는 정보는 별도로 설명한다.

## 계약 5. 대화 수집 상태 전달

### 목적

모둠 공용 기기의 대화 정보가 들어오고 있는지와 실패·종료 상태를 양쪽에 알린다.

### 시작 조건

활동이 진행 중이고 모둠 공용 기기가 준비됐다.

### 정보 범주

- 대기·수집 중·정보 부족·연결 실패·종료
- 정보 유무와 최신성
- 사용자가 취할 수 있는 다시 연결·연결 종료 행동

### 성공의 의미

모둠은 수집 상태를 이해하고, 교사는 정보 부족과 연결 실패를 구분한다.

### 실패의 의미와 책임

대화 정보가 전달되지 않으면 참여 경향을 새로 제공하지 않는다. 모둠은 연결 확인 행동을 보고 교사는 기술 상태를 먼저 확인한다.

### 개인정보 기대

수집 중이라는 표현은 원본 음성의 장기 보존을 뜻하지 않는다. 수집 목적과 보는 주체를 함께 알린다.

## 계약 6. 참여 상태 제공

### 목적

교사가 여러 모둠 가운데 먼저 살펴볼 후보와 이유를 이해한다.

### 시작 조건

활동·모둠 맥락과 판단에 필요한 대화 정보·최신성이 있다.

### 정보 범주

- 고른 참여 경향 또는 한 화자 중심 경향
- 정보 충분성·판단 가능성·최신성
- 익명 화자 표시와 결과 한계

### 성공의 의미

교사는 나무 모둠을 먼저 살펴볼 이유를 설명하고, 바다의 정보 부족과 구름의 연결 실패를 참여 문제와 구분한다.

### 실패의 의미와 책임

정보가 부족하거나 오래됐거나 신뢰할 수 없으면 판단을 유보한다. 자동 해석 실패를 정상 상태로 바꾸지 않는다.

### 개인정보 기대

참여 상태는 수업 지원 신호이며 학생 평가 근거가 아니다. 익명 화자 표시를 학생 이름과 연결하지 않는다.

## 계약 7. 최신성·연결 상태 제공

### 목적

교사가 현재 모둠 상태의 신뢰 가능성과 기술 문제를 이해한다.

### 시작 조건

대화 수집이 시작됐거나 중단·종료됐다.

### 정보 범주

- 최근 정보 있음
- 갱신 중
- 갱신 중단
- 연결 실패
- 종료

### 성공의 의미

교사는 오래된 상태를 현재 참여 상태로 오해하지 않고, 연결 문제에는 기술적 확인을 먼저 한다.

### 실패의 의미와 책임

최신성을 확인할 수 없으면 판단 불가 또는 연결 확인 필요로 표시한다.

### 개인정보 기대

사용자에게 필요한 최신성 의미만 제공하며 구현 수치나 내부 상태를 노출하지 않는다.

## 계약 8. 정보 목적·수명 안내

### 목적

학생·모둠·교사와 실제 도입 검토자가 대화 정보의 목적·열람·보존·삭제·한계를 이해한다.

### 시작 조건

대화 수집 전, 수집 중, 활동 종료 시 각각 안내가 필요하다.

### 정보 범주

- 원본 음성·전사문·익명 화자 표시·참여 지표·요약의 구분
- 정보 사용 목적과 보는 주체
- 확정된 보존·삭제 원칙과 미결정
- 실제 학생 검증 전 결정할 항목

### 성공의 의미

사용자는 수집 목적과 종료 상태를 이해하고, 미결정이 법적 보증처럼 제시되지 않는다.

### 실패의 의미와 책임

안내가 없거나 불명확하면 실제 학생 데이터 사용을 진행하지 않는다. 해커톤은 합성 또는 동의한 성인 데이터로 제한한다.

### 개인정보 기대

이 계약 자체가 법률·정책 적합성을 판정하지 않는다. 실제 도입 전 책임자가 학교급·고지·권리·보존·외부 처리를 결정한다.

## 계약 9. 확장 분석 제공

### 목적

핵심 참여 상태가 동작한 뒤 교사가 대화 단계·주제 관련성·요약·키워드를 추가로 확인하도록 돕는다.

### 시작 조건

핵심 시연 6단계가 동작하고 확장 분석을 위한 정보와 목적이 확인됐다.

### 정보 범주

- 대화 단계
- 주제 관련성·근거
- 요약·키워드
- 분석 최신성·한계

### 성공의 의미

교사는 확장 정보를 보조 자료로 이해하고 핵심 참여 상태와 구분한다.

### 실패의 의미와 책임

확장 분석이 없거나 실패해도 핵심 참여 상태와 오류 구분은 계속 동작한다. 오류를 확정 사실로 표시하지 않는다.

### 개인정보 기대

외부 처리·보존·정정·삭제 원칙은 실제 적용 전에 정한다. 확장 분석은 핵심 시연의 필수 조건이 아니다.

## 시간성과 신뢰성 기대

- 교사는 정보가 최근인지, 갱신 중인지, 멈췄는지 이해해야 한다.
- 모둠 공용 기기는 시작·수집·실패·종료 변화가 교사 상태와 맞는지 확인할 수 있어야 한다.
- 정보가 늦거나 빠졌을 때 이전 상태를 확정 현재 상태처럼 보여 주지 않는다.
- 다시 연결한 뒤에는 참여 경향보다 연결 회복과 새 정보 충분성을 먼저 확인한다.
- 정확한 지연·처리량 목표는 사용자 검증과 구현 선택 뒤 정한다.

## 의미 충돌 해결 원칙

| 충돌 | 우선하는 의미 |
|---|---|
| 참여 편중과 연결 실패가 함께 보임 | 연결·최신성 문제를 먼저 드러내고 참여 판단을 유보한다. |
| 활동 종료와 늦게 도착한 정보가 함께 보임 | 종료 상태를 유지하고 진행 중으로 되돌리지 않는다. |
| 익명 화자 표시와 학생 이름 추정이 충돌 | 자동 동일시하지 않고 익명 화자 한계를 유지한다. |
| 확장 분석과 핵심 참여 상태가 충돌 | 핵심 상태의 출처·최신성을 우선 확인하고 확장 분석은 보조로 둔다. |
| 정보 보존 요구와 최소화 원칙이 충돌 | 실제 목적·책임·보존 기간이 확인될 때까지 미결정으로 남긴다. |
