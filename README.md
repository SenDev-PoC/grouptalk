# 모둠뷰

> 여러 모둠이 동시에 이야기하는 수업에서, 교사가 지금 살펴볼 곳을 빠르게 찾도록 돕습니다.

## 대표 화면과 링크

교사 대시보드에서 모둠별 참여 상태(고른 참여·편중·정보 부족·연결 실패)를 한눈에 비교하고, 모둠 공용 기기는 QR로 입장해 마이크로 토의합니다.

![대표 화면](docs/screenshot.png)

## 최종적으로 해결한 문제

모둠 활동에서는 여러 대화가 동시에 진행됩니다. 교사는 한 모둠만 직접 들을 수 있어, 어느 모둠이 원활한지·어디에 확인이 필요한지를 놓치기 쉽습니다.

### 어떻게 풀었나요?

모둠 공용 기기의 대화를 익명 화자로 듣고, 참여 경향과 연결 문제를 구분해 교사 화면에 보여 줍니다. 교사는 모든 대화를 읽지 않고도 **지금 먼저 살펴볼 모둠**을 고릅니다. 참여 정보는 학생 점수가 아니라 수업 지원 신호입니다.

## 핵심 기능

- **조건 기반 모둠 편성**: 학급 명단과 같이/따로 규칙으로 조를 나누고 수업 전에 확정합니다.
- **QR 한 번에 입장**: 활동 QR·코드로 모둠 공용 기기가 바로 수업에 들어옵니다.
- **실시간 참여 대시보드**: 모둠별 발화 균형과 도움 요청을 보며 먼저 다가갈 모둠을 고릅니다.
- **상태 구분**: 고른 참여, 편중 경향, 정보 부족, 연결 실패를 서로 다른 상태로 보여 줍니다.
- **도움 요청**: 모둠이 손을 들면 교사 화면에서 우선 확인합니다.
- **사후 리포트**: 종료 후 요약·키워드와 전사문을 확인하고 내려받습니다.

## 사용 흐름과 사용 방법

1. 교사가 학급 명단을 등록하고 모둠을 편성한다
2. 활동을 만든 뒤 QR을 공유한다
3. 모둠 공용 기기가 입장하고 교사 시작을 기다린다
4. 교사가 활동을 시작하면 공용 마이크로 대화가 수집된다
5. 교사가 대시보드에서 먼저 볼 모둠을 고른다
6. 활동을 종료하면 리포트와 전사문을 확인한다

- 사용 환경: PC 웹(교사), 휴대폰·태블릿 웹(모둠 공용 기기)
- 사용 조건: 교사만 계정 필요(이메일 가입). 모둠 기기는 QR/링크와 마이크만 있으면 됩니다.

## 기술 스택과 실행 방법

- **화면**: React 19, TypeScript, Vite 8, Tailwind CSS 4
- **서버·백엔드**: Python 3.12, FastAPI, LiveKit Agents
- **AI**: Deepgram nova-3(전사·화자 구분), OpenAI Responses API(요약·키워드·주제 관련성)
- **저장소**: PostgreSQL(Supabase)
- **배포**: Vercel, Railway, LiveKit Cloud

### 폴더 구조

```text
/src                        교사·모둠 웹앱 (React + Vite)
  pages/teacher/            활동 홈, 대기실, 실시간 대시보드, 리포트, 모둠 편성
  pages/student/            QR 입장, 모둠 룸(대기·수집·종료)
  lib/group-status.ts       참여 경향과 연결 문제를 구분하는 표시 규칙
/backend                    FastAPI
  api/livekit_tokens.py     LiveKit 토큰 발급
  api/worker_utterances.py  전사 저장
  api/realtime_analysis/    발화 시간 기반 참여 균형 계산
  api/conversation_analysis/ 요약·키워드·주제 관련성 worker
/backend/livekit-worker     LiveKit → Deepgram 전사 worker
/supabase                   스키마와 migration
/docs                       제품 기획, 백엔드 계약
```

### 설치와 실행

```bash
npm install
cp .env.example .env.local
npm run dev
```

`.env.local`의 Supabase 값을 비워 두면 브라우저 데모 모드로 교사·모둠 화면을 확인할 수 있습니다. 실제 마이크 전사와 분석을 보려면 FastAPI, LiveKit worker, 대화 분석 worker를 함께 실행합니다.

```bash
cd backend
uv sync
uv run uvicorn api.main:app --reload --host 0.0.0.0 --port 8000

cd backend/livekit-worker
uv sync
uv run python -m grouptalk_livekit_worker.agent dev

cd backend
uv run python -m api.conversation_analysis.main
```

- 필요한 환경변수(이름만): VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY, VITE_LIVEKIT_TOKEN_ENDPOINT, DATABASE_URL, LIVEKIT_URL, LIVEKIT_API_KEY, LIVEKIT_API_SECRET, DEEPGRAM_API_KEY, OPENAI_API_KEY, WORKER_API_TOKEN

세부 실행·배포는 [Backend README](backend/README.md)와 [LiveKit worker README](backend/livekit-worker/README.md)를 참고합니다.

## 작동 범위와 한계, 다음 계획

- 지금까지 확인한 범위: 데모 데이터와 동의한 성인 시연으로 교사·모둠 흐름, 상태 전환, 전사·참여 표시를 확인

### 기술적 한계

- 화자가 동시에 말하면 익명 화자 구분이 어긋날 수 있습니다
- 참여 경향은 최근 발화로 계산하며, 학생 능력·태도를 평가하지 않습니다
- 원본 음성은 저장하지 않지만, 전사문 보존 기간과 삭제 절차는 아직 정하지 못했습니다
- 실제 교실의 소음·기기 환경에서 정확성을 보증하지 않습니다
- 해커톤 시연에는 실제 학생 데이터를 사용하지 않습니다

### 다음 계획

- 대화 단계(시작·논의·정리)를 교사 화면에 더 분명하게 보여 주려 합니다
- 정보 종류별 보존 기간과 삭제 방법을 정한 뒤 실제 학교 검증을 준비하려 합니다
- 화자 구분이 반복적으로 실패하는 교실 조건을 더 검증하려 합니다

## 교육 현장에서 사용할 때의 주의사항

- **개인정보 처리 여부**: 처리함 (교사 계정, 학급 명단, 활동 중 전사문)
- **예상되는 위험**: 참여 경향이 학생 평가처럼 읽히거나, 화자 구분 오류로 한 모둠을 잘못 볼 수 있습니다.
- **위험을 줄이려고 한 일**: 화자 A/B/C를 학생 이름과 연결하지 않고, 연결 실패·정보 부족일 때는 참여를 단정하지 않으며, 교사가 직접 모둠을 확인한 뒤에만 개입하도록 했습니다.
- **멈춤 기준**: 참여 카드가 점수로 쓰이거나, 화자 구분이 반복적으로 틀리면 분석 표시를 끄고 교사가 순회만으로 수업을 진행합니다.
- **검증 방법**: 고른 참여·편중·정보 부족·연결 실패 네 상태를 데모와 단위 검사로 구분하는지 확인하고, 실제 음성 smoke는 동의한 성인으로만 진행합니다.

### 입력·전송·저장 정보

- 교사 이메일·표시 이름 — 회원가입 때 입력 — 전송하지 않음(Supabase Auth에만 저장)
- 학생 이름(학급 명단) — 교사가 모둠 편성 때 입력 — 전송하지 않음. 익명 화자와 연결하지 않음
- 원본 음성 — 모둠 공용 마이크 — 전사를 위해 LiveKit·Deepgram으로 전송, 원본은 저장하지 않음
- 전사문·익명 화자 표시 — Deepgram 결과 — PostgreSQL에 저장. 요약·키워드·주제 관련성 분석을 위해 OpenAI API로 전송
- 참여 균형 지표 — 서버가 발화 시간으로 계산 — 전송하지 않음(서버에만 저장)

### 교육적 태도 점검

- 평가·추천·피드백을 프로그램이 대신 확정하지 않게 했나요?: 점검하다 고쳤어요 (참여를 점수로 보여 주지 않고, 교사가 먼저 살펴볼 신호로만 쓰도록 바꿨습니다.)
- 학생이나 교사의 생각을 대신하지 않게 했나요?: 점검하다 고쳤어요 (자동으로 모둠에 개입하지 않고, 교사가 직접 찾아가도록 했습니다.)
- 저장·전달·제출 전에 사람이 확인할 수 있나요?: 아직이에요 (활동이 시작되면 전사는 자동 저장됩니다. 교사가 시작·종료를 결정하고, 학생 화면에서 수집 중임을 알립니다.)
- 기기·계정·조작 문제로 참여에서 빠지는 사람이 없게 했나요?: 아직이에요 (모둠마다 마이크가 있는 공용 기기가 필요하고, 연결이 끊기면 그 모둠의 분석이 멈춥니다. 다만 연결 실패를 참여 부족으로 보이지 않게 했습니다.)
